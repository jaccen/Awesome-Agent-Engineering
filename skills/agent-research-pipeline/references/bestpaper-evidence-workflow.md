# 从 Best-Paper-Writing-Skill 吸收的论文论证与交付方法

## 来源与使用边界

参考 gulucaptain/Best-Paper-Writing-Skill，固定审阅版本 `b9eff99a2130bea960ef1050eacf9f40cb792dd4`（2026-11-25）。原仓库：https://github.com/gulucaptain/Best-Paper-Writing-Skill 。重点审阅 SKILL.md、routing、claim-calibration、figures、experiments、corpus-profile及NOTICE。本文为中文重组与领域适配，未复制论文范例、脚本或模板。本文中改编的工作流按上游CC BY 4.0署名；不改变本项目其他文件许可。上游基础工作另归功于Master-cai/Research-Paper-Writing-Skills及彭思达公开科研笔记，详见上游NOTICE。

适用顺序：用户指定范围、目标venue规范、项目证据纪律优先。获奖样本有选择偏差；55篇分析、5篇留出是上游自述，本轮没有独立复核其逐句标注或泛化能力。数字比例、句长和标点习惯不是质量判定标准，也不是录用率的因果证据。

## 1. 输入先转成研究简报

收到现有摘要也先反向提取事实，避免直接重写后改变贡献含义。复用项目已有主张记录，不创建相互矛盾的第二份事实源。

| 必填项 | 写入内容 | 缺失处理 |
|---|---|---|
| 主问题 | 对象、条件、输入输出、要回答的判断 | 标待明确，不能以宣传目标代替 |
| 最接近工作 | 原始来源、已解决的问题、成立条件 | 标待核实，不编造差距 |
| 具体困难 | 何时出现、可观察现象、实际代价 | 区分观察和解释 |
| 核心想法 | 从困难导出设计的推理 | 未检验机制保留为假设 |
| 结果 | 指标、设置、来源文件、实际比较预算 | 无数据就写TODO，不生成示例成绩 |
| 边界 | 已观察失败、未知条件、成本 | 同步到影响主张的正文位置 |

有材料时先提取并推进；只询问影响论证的关键缺口，不能以填表为由阻塞已有可做工作。

## 2. 按主张类型组织论文

- 方法改进：具体困难→设计理由→与最近方法的可核验差异→质量与成本比较。
- 新能力：输入条件下何种任务此前无法完成→能力定义→任务与成功判据→边界。
- 经验规律或规模研究：独立变量、响应、预算→系统扫描→留出条件验证→实用建议。
- 重新检验：准确引用原判断→原条件与新条件→有区分力的测试→保留或收窄结论。
- 机制分析：现象→竞争解释→可区分预测→控制实验；消融下降本身不充分证明机制。
- 理论：假设与对象→已有结果→新增命题→证明→假设不满足时的限制。
- 数据、基准或平台：旧测量盲区→设计原则→任务/样本/指标→可靠性与泄漏检查→实际可获取范围。
- 测量与系统：实际约束→测量或系统设计→误差、开销与复现条件→适用边界。

混合论文逐项选择证据，不强制整篇只有一种类型。综述不能套成方法改进稿。

## 3. 在起草前建立可追溯映射

复用已有主张—实验—图表记录，至少包括：

| 主张ID | 主张与适用条件 | 最近工作差异 | 方法位置 | 实验/图表及原始产物 | 当前证据状态 | 反证条件/下一步 |
|---|---|---|---|---|---|---|
| C1 | TODO | TODO | TODO | TODO | 计划/探索/已验证/待核验 | TODO |

正文中每段先写要传递的信息及承担的主张ID，再填文字。概念性重复可以合并，但摘要、引言、方法、结果间必要的递进与复述不应机械删除。贡献列表不重复罗列同一组成绩。

数字区分主结论数字、支持数字、表格细节；摘要优先保留支撑主问题的结果，不能只挑赢的数字而隐藏会改变总体结论的失败。绝对值、变化量、单位、分母与预算保持一致。

## 4. 图表先规划后制作

每张图记录：对应主张、图类型、面板、数据/代码来源、所需材料、完成状态、图注结论及适用条件。首页图按论证需要选择失败诊断、成本权衡、新能力示例、规律曲线或资源结构；不强制首页满宽。

方法示意图只画已明确的机制，区分训练与推理、真实可得与特权信息。未知模块保留TODO。结果图缺素材时只建占位和取数计划，禁止以生成图、虚构渲染或示意曲线充当实测结果。图注先交代读者能看到什么，再陈述证据支持的结论；颜色、符号和名称跨图一致。

## 5. 范例学习及检查分级

按段落功能和论文类型找范例，学习信息顺序和推理关系，不拼接原句。只有原文已核实时才能写为来源范例；无法访问则明确标记。

硬错误：虚构引文/数字、正文与表格不一致、缺失单位、图中不存在的模块、未定义符号、错误图号、已提交稿遗留TODO。先修这些，再润色。

软提示：句长、连接词、评价词、摘要数字个数、段落长度和图注长度。保留人工判断及偏离理由，不能把上游获奖样本分位数设置成硬门槛。LaTeX编译通过仅证明构建成功，不能证明内容真实。

## 6. 按阶段交付

构思：研究简报、路由理由、最小区分性验证。起草：章节骨架、主张映射、图表计划与TODO。修改：原句→改句→原因→是否改变主张范围的变更表。投稿检查：证据缺口、引用和图表一致性、格式与构建结果，按对核心结论影响排序。

## 不采纳的上游规则

不采用“摘要/引言禁止局限”“只陈述获胜设置”“核心想法不得写成假设”“消融即可断言因果责任”“禁止某种标点即报硬错误”。影响解释的条件和失败必须就地表达，不能仅移入局限章节。也不照搬其获奖语料或第三方模板许可。

## Agent领域适配

比较必须记录模型版本、提示与工具权限、运行预算、采样次数、任务独立单位、环境状态、失败重试和评测器。平台、harness与基础模型变化不得混作单一方法收益。效率比较同时列成功率、费用和时延；安全结论注明威胁模型、攻击预算与未覆盖攻击面。
